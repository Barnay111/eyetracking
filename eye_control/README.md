# Eye Control — управление компьютером взглядом (MVP)

Кроссплатформенное (macOS + Windows) приложение на Python/PySide6: обычная веб-камера →
точка взгляда → системный курсор, dwell-клик, экранная клавиатура и озвучка.

## Установка

Проверено на **Python 3.12** (mediapipe 1.2.3, PySide6 6.12, numpy 2.5).

```bash
cd eye_control
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Модель `assets/face_landmarker.task` (MediaPipe Face Landmarker с радужкой) уже лежит в репозитории.

Если PyPI качается медленно, можно ставить через зеркало Яндекса с PyPI как запасным источником
(на зеркале есть не все пакеты):

```bash
uv pip install -p .venv/bin/python -r requirements.txt \
  --index https://mirror.yandex.ru/pypi/web/simple \
  --default-index https://pypi.org/simple --index-strategy unsafe-best-match
```

### Права ОС

* **macOS**
  * *Камера* — разрешить приложению, из которого запускается Python (Terminal, iTerm, PyCharm…).
  * *Универсальный доступ* (Accessibility) — обязательно, иначе курсор и клики не работают.
    При запуске без этого права программа покажет окно с кнопкой «Открыть настройки».
  * Для глобальной горячей клавиши — *Мониторинг ввода*. По умолчанию на macOS она выключена
    (`global_hotkey_enabled` в `~/.eye_control/settings.json`): слушатель клавиатуры pynput
    нестабилен на новых версиях macOS.
* **Windows** — Параметры → Конфиденциальность → Камера. Клики в окна, запущенные от администратора,
  работают только если Eye Control тоже запущен от администратора (ограничение UIPI).

## Использование

1. При первом запуске калибровка стартует автоматически: смотрите на зелёную точку
   (9 точек, ~2 с на точку). Голову держите ровно. `Esc` — отмена.
   Профиль сохраняется в `~/.eye_control/profiles/default.pkl` и загружается при следующем запуске.
   После 9 точек идут 5 синих проверочных: по ним считается реальная точность (модель их не
   видела), затем они тоже добавляются в обучение. Сила регуляризации Ridge подбирается
   автоматически (leave-one-point-out), выбросы внутри каждой точки отбрасываются.

   **Количество точек** выбирается в Настройках: 9 / 16 / 25 / 35 / 48 / 63 / 80 / 99 (по
   умолчанию 35, порядок «змейкой», отдых каждые 20 точек). Затем идёт ~20 с **слежения**: жёлтая
   точка плавно летает по экрану, нужно следить за ней глазами.

   **Память между сессиями.** Каждая калибровка (даже прерванная через Esc) и каждое дообучение
   сохраняются в `~/.eye_control/data/sessions/*.npz`. Модель обучается на всей истории с тем же
   экраном (до 40 000 самых свежих сэмплов). Текущая сессия весит ×3, дообучение ×2, прошлые
   сессии ×1. Чем больше сессий в разных позах и при разном свете, тем устойчивее трекинг.
   Журнал действий (клики, режимы, пауза, результаты калибровок) пишется в
   `~/.eye_control/data/usage.jsonl`; набранный на экранной клавиатуре текст туда не попадает.

   **Дообучение на ходу:** каждое нажатие взглядом кнопки панели, клавиатуры или настроек
   добавляет кадры фиксации с меткой «центр кнопки», и модель переобучается. Если прогноз
   был дальше 350 px от кнопки, это считается промахом и не учитывается. Профиль сохраняется
   каждые 5 дообучений и при выходе.
   **Быстрая подстройка (⚡).** При каждом запуске программа показывает 5 точек, это около
   8 секунд. Каждый день поза, расстояние и свет немного другие: модель, обученная на прошлых
   сессиях, ошибается на новой примерно на 140 px. Дообучение на 5 точках сегодняшней позы с
   большим весом снижает ошибку примерно до 77 px. Это почти как полная калибровка на 63 точки
   (проверено на сохранённых сессиях). Кнопка «⚡ Подстройка» на панели повторяет её, если вы
   пересели. В Настройках подстройку при запуске можно выключить, флаг `--no-adjust` пропускает
   её один раз.

   **Поправка сдвига.** Последние 8 «якорей» (точки подстройки и клики по своим кнопкам) дают
   общий сдвиг прогноза, который применяется сразу, ещё до переобучения. Клики этого запуска
   весят в обучении ×10, точки подстройки ×100.

   **Тренировка (🏋️) по вашему экрану.** Программа находит реальные цели через Accessibility:
   значки Dock, пункты меню, значки строки меню справа (Wi-Fi, батарея, часы) и кнопки панели.
   Потом подсвечивает их по очереди (≈ 2 с на цель, ≈ 75 с на ~38 целей). Кадры фиксации
   идут в обучение с меткой «центр цели»: в этом запуске с весом ×30, затем сохраняются как
   отдельная сессия `*-exer`. Края экрана, где веб-камера ошибается сильнее всего, получают
   данные ровно там, куда вы смотрите при работе. Остановить можно, задержав взгляд на «Стоп»;
   уже собранное сохраняется.

   **Стабилизация курсора.** «Мёртвая зона» 35 px (Настройки → «Стабилизация курсора»,
   0 — выкл.). Пока взгляд в пределах зоны, курсор стоит на месте. Резкий перевод взгляда
   переносит его сразу, смещение на 1–3 радиуса — через 3 кадра. На синтетическом дрожании
   20 px движение между кадрами падает с 33 px до 1 px.

   **Нейросеть (эксперимент).** Во время калибровки к каждому кадру записывается ответ
   нейросети взгляда MobileOne-S0. Это модель в стиле L2CS-Net, обученная на Gaze360
   ([yakhyo/gaze-estimation](https://github.com/yakhyo/gaze-estimation), MIT), ~5–9 мс на кадр.
   Веса скачиваются отдельно: `scripts/download_models.sh` (без них всё работает). В рабочую модель она пока не входит. `scripts/eval_neural.py` сравнивает точность с ней и
   без неё. Если выигрыш подтвердится, её включат в признаки.
2. Задержите взгляд на месте (радиус R, время T) — вокруг точки взгляда заполняется кольцо,
   затем выполняется клик. Для повторного клика отведите взгляд или подождите паузу между кликами.
3. Панель справа:
   * **Калибровка** — повторная калибровка (после смены освещения/позы).
   * **Пауза** — режим «только чтение»: клики отключены. Выход — удерживать взгляд на
     «Возобновить» 2 с (сначала нужно отвести взгляд от кнопки). Горячая клавиша: `Ctrl+Alt+P`.
   * **Клавиатура** — экранная клавиатура RU/EN. «Прямой ввод: ВКЛ» — символы сразу печатаются
     в активное окно; «ВЫКЛ» — текст копится и вставляется кнопкой «Вставить» через буфер обмена.
     «Озвучить» — офлайн TTS (macOS `say`, Windows SAPI5 через pyttsx3).
     **Подсказка слов:** над клавишами 4 крупные кнопки с самыми частыми словами, которые
     начинаются с набранных букв (словарь 30 000 слов RU/EN). Выбор подсказки дописывает слово
     и пробел. Клавиши набора и подсказки срабатывают быстрее обычного клика: «Dwell клавиш»,
     по умолчанию 0.8 с. Набранный текст и выбранные слова нигде не сохраняются.
   * **Команды** — панель управления окнами и приложениями. Сочетания клавиш уходят в активное
     приложение, его имя видно в заголовке («Команды → Safari»):
     ◀ Назад, Вперёд ▶, ⇄ Другое окно (⌘Tab), 🔎 Поиск (Spotlight + экранная клавиатура:
     так открывается любое приложение), ▲/▼ прокрутка окна, на которое вы смотрели последним,
     ＋ Новая вкладка, ⤢ Во весь экран, — Свернуть, ▢ Закрыть окно, ✕ Выйти из приложения
     (в два нажатия). Ниже — сетка приложений из вашего Dock, часто запускаемые идут первыми.
     Дополнительные приложения можно добавить в `command_apps` в `~/.eye_control/settings.json`
     (на Windows — пути к .exe/.lnk, других источников там нет).
   * **Открыть ×2** — одноразовый двойной клик (открыть файл, папку, приложение). Нажмите
     кнопку взглядом: она станет жёлтой («Жду цель…»), кольцо взгляда тоже станет жёлтым с
     меткой «×2». Задержите взгляд на значке — произойдёт двойной клик, затем режим сам
     вернётся к обычному клику. Повторное нажатие кнопки или пауза отменяют его.
   * **Лупа** — одноразовое увеличение для мелких целей. Нажмите «🔍 Лупа», затем задержите
     взгляд рядом с целью: область 250×156 вокруг неё откроется увеличенной в 3 раза.
     Задержите взгляд на нужном месте в лупе, и клик (или двойной клик, если включён «×2»)
     произойдёт в соответствующей точке настоящего экрана. Ошибка трекинга при этом
     уменьшается в 3 раза. «✕» или 15 с бездействия закрывают лупу. На macOS нужно право
     «Запись экрана».
   * **Режим клика** — постоянный режим, по кругу: клик → двойной → правый → скролл. В режиме скролла взгляд в
     верхних/нижних 20 % экрана прокручивает страницу.
   * **Настройки** — камера, время dwell (0.8–2.5 с), dwell клавиш (0.4–2.5 с), радиус фиксации,
     радиус магнита (0 — выкл.), сглаживание, пауза между кликами, сохранение/загрузка профиля. Все параметры меняются кнопками «−/+», удобными для взгляда.
4. **Магнит** (Настройки → «🧲 Магнит», по умолчанию ВКЛ). Взгляд притягивается к ближайшей
   кнопке, ссылке, пункту меню, значку Dock или иконке в радиусе 70 px (меняется в Настройках). Цель обводится
   рамкой, курсор встаёт в её центр, а dwell считается по цели. Поэтому кольцо заполняется,
   даже если взгляд «гуляет» на 50–80 px. Цели других приложений ищутся в фоновом потоке:
   на macOS через Accessibility API, на Windows через UI Automation (пакет `uiautomation`;
   на реальном Windows пока не проверялось).
5. Панель, клавиатуру, команды и настройки можно перетащить мышью за фон.
6. **Выход** — в два нажатия: после первого кнопка спрашивает «Точно выйти?», нужно отвести
   взгляд и в течение 4 с нажать снова. `kill`/`Ctrl+C` тоже завершают программу штатно,
   с сохранением профиля и дообучений.

### Приложение macOS

```bash
scripts/build_mac_app.sh           # ~/Applications/Eye Control.app
scripts/build_mac_app.sh --login   # + автозапуск при входе в систему
```

Это лёгкий бандл с иконкой: он запускает `main.py` из папки проекта через её `.venv`. Если
переместить папку, пересоберите его. Логи пишутся в `~/.eye_control/app.log`. Права (Камера,
Универсальный доступ, Запись экрана) выдаются приложению «Eye Control» отдельно от Терминала.

Кнопки собственных окон нажимаются по взгляду программно, без системного клика. Поэтому
приложение не забирает фокус у окна, в которое вы печатаете.

## Архитектура

```
eye_control/
├── main.py              # Qt-приложение, проверка прав, связывание модулей, цикл обработки взгляда
├── config.py            # Settings (JSON в ~/.eye_control), раскладки клавиатуры
├── core/
│   ├── gaze_engine.py   # QThread: камера → MediaPipe → признаки (+поза головы) → Ridge → One Euro
│   ├── magnet.py        # магнит: цели через Accessibility (macOS) / UI Automation (Windows)
│   ├── predictor.py     # подсказка слов (assets/words_ru.txt, words_en.txt)
│   ├── os_controller.py # курсор (HiDPI), клики, скролл, DwellDetector, горячие клавиши, права ОС
│   └── tts_engine.py    # say / pyttsx3
└── ui/
    ├── overlay.py        # прозрачный click-through оверлей (по окну на монитор)
    ├── calibration_ui.py # полноэкранная калибровка (9–99 точек + слежение + проверка)
    ├── toolbar.py        # плавающая панель
    ├── keyboard_ui.py    # экранная клавиатура + TTS
    ├── magnifier.py      # лупа ×3 для точного клика
    ├── commands_ui.py    # панель команд: окна, вкладки, прокрутка, запуск приложений
    ├── settings_ui.py    # окно настроек
    └── common.py         # стили, «взглядовое» нажатие кнопок
```

**Откуда что взято.** Из EyeTrax (MIT) взято извлечение признаков: 3D-ориентиры глаз и радужки
MediaPipe, нормализованные в систему координат головы, плюс yaw/pitch/roll. К ним добавлены
положение и масштаб лица в кадре, чтобы лучше компенсировать сдвиг головы. Регрессия — Ridge,
тоже по образцу EyeTrax. Остальной код написан заново: One Euro Filter, dwell-логика, UI на
одном фреймворке, работа с HiDPI. `cv2.imshow` и tkinter не используются.

**Словари подсказок** построены по частотным спискам [wordfreq](https://github.com/rspeer/wordfreq)
(данные — CC BY-SA 4.0).

**Камера.** Признаки считаются в нормированных координатах кадра, поэтому важно поле зрения,
а не разрешение. У камеры MacBook 640×480 — это уменьшенный полный кадр 1760×1328, а 1280×720 —
обрезанный сверху и снизу. Поэтому разрешение поднимают до 1760×1328 (`camera_width`/
`camera_height` в settings.json): старые сессии остаются совместимыми.

**HiDPI.** Все координаты внутри приложения — логические точки Qt. На macOS это совпадает с
точками Quartz: курсор двигается через pynput, приложения получают hover-события. На Windows
Qt 6 включает Per-Monitor DPI v2, и курсор двигается через `QCursor.setPos`. Qt сам пересчитывает
координаты в физические пиксели с учётом масштаба каждого монитора.

## Ограничения MVP

* Калибровка выполняется на основном мониторе. На других экранах точка экстраполируется, и
  точность ниже.
* Типичная точность веб-камерного трекинга — 50–150 px. Поэтому радиус dwell по умолчанию
  45 px, а кнопки делаются крупными.
* Профиль калибровки — pickle. Загружайте только свои файлы.
